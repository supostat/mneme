# HANDOFF: used_notes — что меняется для скиллов плагина

Контракт для агента mneme-plugin. Движок научился замыкать петлю полезности: он и раньше знал,
какие заметки **поднял в бандл** фазы, но не знал, какие из них **пригодились**. Теперь харвест-вызов
может это сказать. Скиллы здесь НЕ пишутся — документ перечисляет, что плагинной стороне нужно
отразить.

## workflow_step: поле used_notes <!-- HANDOFF-USED-NOTES-FIELD -->

- Инструмент `workflow_step` принимает НОВОЕ опциональное поле `used_notes` — массив
  `{ id, evidence }`.
- Поле едет **вместе с `harvest_artifacts`**, в том же вызове, который закрывает фазу. Отдельного
  вызова нет и не будет: второй вызов — это второй шанс забыть.
- `id` — id заметки из recall-бандла ЭТОЙ фазы. `evidence` — строка, называющая место, где заметка
  повлияла на работу.

```
workflow_step {
  run_id: "…",
  harvest_artifacts: [ … ],
  used_notes: [ { id: "01ARZ…", evidence: "её правило порядка прагм задало openWritableDatabase" } ]
}
```

## Правило формулировки: что считается использованием <!-- HANDOFF-USED-EVIDENCE -->

**used = ты можешь назвать конкретное место в диффе или в решении, где заметка повлияла.**
Три типичные формы влияния:

- **следование контракту** — заметка задала форму, которую ты воспроизвёл;
- **избегание названной грабли** — заметка предупредила, и ты сделал иначе;
- **цитата решения** — заметка содержала решение, которое ты применил как есть.

**Совпадение темы — НЕ использование.** Заметка про SQLite в бандле фазы про SQLite, которую ты
прочитал и ничего из неё не взял, — не «used». Это и есть та самолесть, ради защиты от которой
поле требует `evidence`: заявка, под которую нельзя подписать место, — не заявка.

Валидная evidence называет место:

- `«из неё взято, что harvest — закрывающая директива: поэтому проверка встала до harvestPhase»`
- `«её различие null/[] стало разделением двух метрик в formatUseStats»`
- `«предупреждение про цикл импортов увело контракт в отдельный модуль used-notes.ts»`

Невалидная evidence (место не названо — переформулируй или не объявляй заметку used):

- `«полезная заметка»`
- `«про то же самое»`
- `«учтено»`
- `«помогло сориентироваться»`

## Отказ вызова: чего ждать <!-- HANDOFF-USED-REFUSALS -->

Декларация проверяется ДВАЖДЫ, и оба отказа роняют **весь вызов** — харвест не применяется, в лог
не попадает ничего:

- **форма** (граница SDK): `id` не соответствует грамматике id заметки, или `evidence` пустая
  после trim. Такой вызов отвергается ещё до движка — в логе не остаётся даже `tool_error`.
  Текст требования: `evidence must name where the note influenced the work`.
- **содержание** (движок): id, которого не было в бандле этой фазы, —
  `declared note was not in this phase's recall bundle, so it cannot have been used`.
  Фаза, чей recall прошёл до этой версии схемы, вообще не имеет записанного состава бандла —
  `this phase's recall bundle composition was never recorded, so a usage declaration cannot be checked against it`.
- **не туда прицепил**: `used_notes` без `harvest_artifacts` —
  `used_notes rides the harvest submission: declare the notes you leaned on in the same call that closes the phase`.

Практический вывод для скилла: id для декларации бери ИЗ БАНДЛА, который движок выдал этой же фазе,
а не из памяти о прошлых фазах и не из recall-вызова, сделанного руками.

## Пустой список и отсутствие поля — РАЗНОЕ <!-- HANDOFF-USED-EMPTY -->

| что отправлено | что это значит | как читается метрикой |
|---|---|---|
| поля нет | вызов не инструментирован (скилл ещё не обновлён) | вне числителя покрытия |
| `used_notes: []` | «я посмотрел, ничего не пригодилось» | честный ноль в precision |
| `used_notes: [{…}]` | объявленные использования | числитель precision |

`[]` — **легальный и честный ответ**, он принимается даже когда состав бандла неизвестен. Не
выдумывай использование, чтобы «не было пусто»: пустой список портит метрику меньше, чем ложная
заявка, — он её как раз и лечит.

## NEUTRALITY: цифры скиллам не показываются <!-- HANDOFF-USED-NEUTRALITY -->

Метрика, которую питает это поле (precision-of-use и покрытие деклараций), живёт ТОЛЬКО в выводе
`stats` — для человека. Она не входит в ранжирование recall, не возвращается в ответах
`workflow_step` и не должна попадать ни в один текст, где скилл вырабатывает рекомендацию. Агент,
знающий свой собственный балл полезности, начинает оптимизировать балл вместо правды (Goodhart) —
ровно тот же запрет уже действует для agreement-метрики человеческого гейта.

Пока скиллы не обновлены, метрика показывает «покрытие 0%». Это честное состояние, а не дефект:
никто ещё не декларировал.
